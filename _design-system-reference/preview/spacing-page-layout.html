Applies to
All app screens (/, /today, /profile, /events/todo, /events/calendar, /events/countdown). The container sits inside the route group's app shell, below the StatusBar + AppHeader + ScreenTabs chrome and above the BottomNav.
Documented exceptions — Lock screen (/lock) is OS chrome and uses its own iOS-spec padding, not the brand standard. Calendar (/events/calendar) keeps pb-[80vh] on the cards container so any WeekStrip pill click can position its target AgendaCard flush to the top of the viewport — the 80vh runway is a scroll-positioning spec, not a visual padding choice. The page's TOP padding (pt-8) still applies to the sticky chrome. The /components sandbox uses its own dense grid layout to fit primitive matrices and is exempt from the screen padding standard.
Rationale — 16px sides on a 414px-wide mobile viewport leaves the inner content column at 382px — comfortable for a single column of card content without feeling cramped near the bezel. 32px top + bottom places content below the chrome header by a clear visual gap (no abrupt collisions) and prevents the last item from being flush with the BottomNav. Both values consume canonical 4pt-grid tokens (--space-4 and --space-8).
